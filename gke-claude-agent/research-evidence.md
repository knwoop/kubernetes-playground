# Claude Code in a GKE Pod (claude -p via kubectl exec) research evidence (2026-11-01)

## Frame
- Issue: kubernetes-playground-mg1 "Spin up GKE for AI agent platform (Claude Code agent)". Commit fec96d1 on branch kubernetes-playground-mg1-gke-claude-code-agent-plan. Docs fetched 2026-11-01; docs mention Claude Code up to v2.1.302.
- Purpose: feed a plan for a PoC that runs Claude Code in a Pod on GKE and runs `claude -p` from the user's laptop via `kubectl exec`, checking that sessions carry over between calls. Slack and the gateway are out of scope.
- Scenario (confirmed with user): one person, own claude.ai subscription; a human runs `claude auth login` inside the Pod; Pod is a non-root StatefulSet (replicas 1) in its own Namespace, ServiceAccount without GCP permissions, PVC at CLAUDE_CONFIG_DIR (e.g. /home/claude/.claude), cwd /workspace/repo, managed-settings.json from a read-only ConfigMap (forceLoginMethod claudeai, forceLoginOrgUUID placeholder, deny rules on the credentials file), optional NetworkPolicy. Wrapper `claude-pod <key> "<prompt>"`: UUIDv5 from key; session file absent -> `--session-id`, present -> `--resume`; `--output-format json`; `--allowedTools` Read/Grep/Glob. Forbidden: CLAUDE_CODE_OAUTH_TOKEN, ANTHROPIC_API_KEY, ANTHROPIC_AUTH_TOKEN; reading `.credentials.json`; modifying the binary; automating login.
- Live cluster: not checked. `kubectl` is not installed and no kube config exists on this machine (docker and gcloud exist). Cluster type, node arch, storage classes, NetworkPolicy enforcement, current context: could not determine.
- Done questions: Q1 install, non-root image, config/credential/transcript storage. Q2 CLI session semantics, JSON output, tool restriction, session file layout. Q3 managed settings and deny rules. Q4 GKE side. Q5 login flow, billing, terms, endpoints.
- Questions for the plan referenced in "bears on": P1 tool restriction mechanism; P2 how credentials-file protection is enforced and verified; P3 create-vs-resume logic and concurrency; P4 how Claude Code is installed in the image; P5 forceLoginOrgUUID placeholder and org; P6 egress restriction method; P7 storage and volume ownership; P8 subscription/terms fit; P9 cluster type and image platform; P10 Pod identity.
- Source abbreviations: docs = https://code.claude.com/docs/en/<page>. Findings files (scratchpad research/01..04) hold the longer tables. "verified" = checked by me with a second fetch; otherwise sub-agent only.
